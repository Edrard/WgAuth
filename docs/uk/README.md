# WgAuth

Бібліотека PHP 8.5 забезпечує WG-вхід, одноразовий стан callback, перевірку власника токена, оновлення й відкликання токенів. Канонічні інструкції встановлення, HTTPS/session-конфігурації й приклади: [англійський README](../../README.md).

Застосунок створює `AuthClient` і `WgAuth` із власним сховищем стану. `beginLogin()` повертає адресу входу; `completeLogin()` споживає одноразовий стан і перевіряє власника токена. WG-токени не замінюють сесію застосунку й не повинні потрапляти в журнали або клієнтське сховище.

## Необов'язковий логер

```php
/** @var \Psr\Log\LoggerInterface $logger Логер зовнішнього застосунку. */
$client = new \edrard\WgAuth\AuthClient($applicationId, logger: $logger);
```

Останній необов'язковий аргумент `logger` передається типовому `GuzzleAuthTransport`. Власний транспорт налаштовуйте окремо; його конфігурація не замінюється. Без логера або з null використовується `NullLogger`: робота не потребує журналу.

Типовий транспорт трактує `NullLogger`, включно з його підкласами, як явне вимкнення діагностики. Для власного логера із записом повідомлень реалізуйте `LoggerInterface` або успадкуйте `Psr\Log\AbstractLogger`.

Типовий транспорт дає максимум одне warning на невдалий запит: безпечна категорія та числові providerCode/httpStatus. Успішні запити, локальна валідація, стан і перетворення токенів не логуються. URL, параметри, callback, токени, нікнейми, відповіді й об'єкти винятків не додаються до контексту.

Винятки та Error логера не замінюють початковий `AuthException` або його коди. Повторів запиту чи доставки логів немає. Сховище, фільтри й утримання належать застосунку. PSR-3 синхронний; для доставки без очікування використовуйте логер із власною чергою.

## Перевірки

Після `composer install`: `composer test`, `composer analyse`, `composer format:check`. Наявний форматер — PHP-CS-Fixer із PSR-12. Інструкції прикладів CLI/HTTPS наведено в англійському README; реальні зміни токенів потребують окремого рішення застосунку.
